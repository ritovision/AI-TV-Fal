## Follow-up: Escape and cursor state

- On the desktop Android TV emulator, the **Escape key** is the emulator's normal Back control; our Activity treats Android KEYCODE_BACK and KEYCODE_ESCAPE alike. On a physical Google TV remote, this is the dedicated **Back/Return** button, not D-pad Left.
- The cyan overlay cursor is a remote-driven marker: it starts centered, moves using D-pad arrows in Cursor mode, and is not the same as the host Windows mouse pointer.
- New candidate hides that overlay automatically whenever the TV IME is visible, based on WindowInsets, and restores it when the IME is dismissed. Its previous coordinate is preserved.
- The emulator's real mouse hover and touch-down now synchronize the cyan marker, avoiding a misleading center-position cursor when developing with a mouse. This doesn't replace D-pad input on a real television.
- A live benign test confirmed that tapping the **current** fal Agent prompt opens Android's native IME, and a single Back event hides it without changing /dashboard or closing the app. An earlier missed click was due to the signed-in site's layout shifting after loading; the test tap had been above the prompt.
- Kotlin debug build passed. Updated APK installed with `adb install -r` on the Google TV AVD, preserving signed-in app data. Visual checks passed: cyan pointer hidden with TV IME visible; one Back hid the keyboard without leaving fal dashboard; pointer reappeared at the last editor location.
