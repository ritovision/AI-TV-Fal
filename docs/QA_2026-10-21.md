# AI-TV emulator smoke-test checkpoint — 2026-10-21

## Verified today

- Android TV emulator boots in **headed mode** on the Windows desktop, using official Google TV Android 36 x86_64 system image and AVD name `AI_TV_GoogleTV_API36`.
- ADB identifies the device specifically as `emulator-5554` with `ro.boot.qemu.avd_name=AI_TV_GoogleTV_API36` and `sys.boot_completed=1`. Actual ADB serial can change on next boot; always verify name.
- Existing `Pixel_9_API_35` headless emulator was not stopped or reset. Physical phone was not touched.
- `./gradlew --no-daemon --max-workers=1 :app:assembleDebug` **passed** in WSL2 (first build ~1m39s). Initial cached-only build failed due to missing Kotlin artifact, fixed by using network resolution and explicit AGP plugin module mapping in `settings.gradle.kts`.
- Android package `com.ritovision.aitv` installed to the correct Google TV emulator via `adb -s emulator-5554 install -r`; launching `.MainActivity` succeeds.
- The real `https://fal.ai/` homepage visibly renders inside the full-screen WebView at 1920x1080.
- Cursor mode: simulated D-pad Right x5 moves the on-screen cursor right by the expected increment; observed on a TV screenshot.
- Long press Select / D-pad Center successfully switches to focus mode; cursor disappears and a mode hint appears.
- Focus mode: directional key causes a live webpage BUTTON to gain `data-aitv-focus=true`; DevTools identified its DOM bounding box, confirming the injected focus script is active.
- Long press Back brings up the native browser housekeeping menu, including Back, Forward, Refresh, fal.ai Home, and mode switch; observed visibly.
- **Google TV setup note:** `device_provisioned=1`, `user_setup_complete=1`, and Android AccountManager reports **0 accounts**. Email-only Google TV first-run setup did *not* authenticate a Google account. This is independent from logging into fal.ai.

## Not yet verified

- Actual click-through on a fal.ai button using custom cursor Select, and the complete auth redirect flow.
- Google OAuth inside the WebView and signed-in cookie persistence through app restart / emulator cold boot. **User must enter credentials personally.**
- Precise spatial navigation effectiveness across the signed-in fal editor.
- Native TV virtual keyboard activation and text submission within fal forms.
- Each menu command's navigation effect (only opening the menu was validated).
- Any Sony hardware behavior.
- Voice dictation (explicitly deferred).

## Safety and space

- No secrets, account addresses, or authentication tokens were stored in Git.
- All screenshots are disposable, untracked `captures/` output; not committed. Captures may be removed after observation.
- E: remains disposable/unreliable; recovery scripts and image checksums are committed on C:.
- Headed Google TV emulator can remain running while the user explores it. Stop only this AVD if necessary; do not terminate other emulators.

## UI controls in this build

- D-pad arrows: move pointer in Cursor mode; move DOM focus in Focus mode.
- Short OK: tap at pointer / activate the focused DOM control.
- **Long OK:** toggle Cursor/Focus mode.
- Short Back: previous webpage if available; otherwise open menu.
- **Long Back:** browser menu; some remotes may also expose a Menu key.
- Menu: Back, Forward, Refresh, fal.ai Home, Switch mode, Close.

This checkpoint is a smoke test, **not final release acceptance**.
